# Configuration reference

Environment variables are read once at process startup by `BrokerConfig.from_env()`.

## Parsing rules

| Value type | Parsing |
| --- | --- |
| Boolean | `1`, `true`, `yes`, and `on` are true, case-insensitive. Any other set value is false. |
| Integer | Parsed with `int()`. Empty values use the default. |
| Float seconds | Parsed with `float()`. |
| CSV | Comma-separated, trimmed, empty items ignored. |
| Path list | Colon-separated, expanded with `~`, resolved to absolute paths, empty items ignored. |
| JSON | Parsed as UTF-8 JSON object. Invalid shape fails startup or request handling. |
| `CODEX_BIN` | Parsed with shell-like splitting, then broker appends Codex subcommands. |

## Server and authentication

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_HOST` | `127.0.0.1` | Host interface for the HTTP server. Docker sets `0.0.0.0`. |
| `CODEX_BROKER_PORT` | `3400` | HTTP server port. |
| `CODEX_BROKER_INTERNAL_KEY` | unset | Shared internal API key. Required unless unauthenticated dev mode is enabled. |
| `CODEX_BROKER_INTERNAL_KEY_FILE` | unset | File containing the internal API key. Used only when `CODEX_BROKER_INTERNAL_KEY` is not set. |
| `CODEX_BROKER_ALLOW_UNAUTHENTICATED` | `false` | Development escape hatch. When true and no key is configured, product routes accept unauthenticated requests. |
| `CODEX_BROKER_OWNER_HASH_KEY` | persistent generated key | Explicit HMAC key for owner and auth-principal hashes. When unset, the broker creates `state/owner-hash.key` once and reuses it across API-key rotations. |
| `CODEX_BROKER_OWNER_HASH_KEY_FILE` | unset | File containing the owner-hash HMAC key. Mutually exclusive with `CODEX_BROKER_OWNER_HASH_KEY`. |
| `CODEX_BROKER_AUTH_PRINCIPAL_MAP_JSON` | unset | Trusted JSON object mapping owner ids to the Codex account identities they may use. |
| `CODEX_BROKER_AUTH_PRINCIPAL_MAP_FILE` | unset | File containing the same mapping. Mutually exclusive with the JSON variable. |
| `CODEX_BROKER_OPENAI_COMPAT_BINDINGS_FILE` | unset | JSON file mapping SHA-256 compatibility-key digests to fixed broker identity, profile, policy, workspace, and model-alias settings. |

Only `GET /healthz` and `GET /readyz` are unauthenticated by design.
`/metrics`, `/openapi.json`, owner-scoped `/v1/owners/...` routes, and
`/v1/bundles/inline` require the internal broker key unless the development
override is active.

`/v1/models`, `/v1/responses...`, and `/v1/chat/completions` always require a
compatibility key from `CODEX_BROKER_OPENAI_COMPAT_BINDINGS_FILE`. The internal
broker key is not valid on those routes, and a compatibility key is not valid
on native routes.

### OpenAI-compatible identity bindings

The binding file is a JSON object keyed by a lowercase SHA-256 digest prefixed
with `sha256:`:

```json
{
  "sha256:<digest-of-client-key>": {
    "ownerId": "service-account-1",
    "authPrincipalId": "shared-codex",
    "profile": "default",
    "configProfile": "default",
    "hostApp": "openai-sdk",
    "bundleId": "example-chat-v1",
    "cwd": "/workspaces/app"
  }
}
```

Generate a digest without storing the raw key:

```bash
printf '%s' "$COMPATIBILITY_KEY" | shasum -a 256
```

`ownerId` is required. Omitted `profile` and `configProfile` values use
`default`; omitted `hostApp` uses `openai-compatible-api`. Every other field is
optional. Unknown fields, malformed digests, empty selectors, and invalid alias
maps fail broker startup.

Broker includes `gpt-5.6` → `gpt-5.6-sol` by default. Optional `modelAliases`
entries are merged on top, with custom entries taking precedence for that
binding. Omitting `modelAliases` or supplying `{}` retains the default.
An alias requires its target to be available in Codex's model catalog.

The binding is the complete caller authorization decision. OpenAI request
bodies and headers cannot select owner, auth principal, profile, configuration
profile, host app, bundle, workspace, or model aliases. An
`authPrincipalId` in the binding must still satisfy
`CODEX_BROKER_AUTH_PRINCIPAL_MAP_JSON` or
`CODEX_BROKER_AUTH_PRINCIPAL_MAP_FILE`.

The raw key is distributed to the client separately. The broker compares its
digest in constant time and does not persist the raw key or digest in turns,
events, audits, or public objects. See
[OpenAI compatibility](../integrations/openai-compatibility.mdx) for client
setup and the supported API.

## Filesystem and policy roots

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_DATA_DIR` | `.data` | Persistent broker data root. Contains SQLite state, auth homes, inline bundles, and overlays. |
| `CODEX_BROKER_ALLOWED_WORKSPACE_ROOTS` | current working directory | Colon-separated host workspace roots. Request `cwd` values and bundle `allowedPaths` must be inside these roots unless the broker overlay root is used. |
| `CODEX_BROKER_ALLOWED_BUNDLE_ROOTS` | current working directory | Colon-separated reviewed bundle roots. Mounted bundle files, mounted skills, and mounted prompts must be inside these roots. |

Derived paths under `CODEX_BROKER_DATA_DIR`:

| Path | Purpose |
| --- | --- |
| `state/broker.sqlite` | SQLite state store. |
| `state/owner-hash.key` | Mode-`0600` persistent owner-hash key. Back it up with state and auth data. |
| `auth/principals/<auth-principal-hash>/profiles/<profile>/codex-home` | Per-principal/profile Codex home. |
| `workspaces/runtime-homes/<auth-principal-hash>/profiles/<profile>` | Non-secret `HOME` for the matching app-server child. |
| `bundles/inline/<digest>/bundle.json` | Accepted inline bundle content. |
| `workspaces/overlays/<turn-id>` | Per-turn generated files, symlinks, MCP config, and hosted-tool config. |

## Codex command and credentials

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BIN` | `codex` | Codex CLI command. May include arguments because the value is split with `shlex.split()`. |
| `CODEX_CREDENTIAL_STORE` | `file` | Value written to each auth-principal/profile `config.toml` as `cli_auth_credentials_store` and passed to Codex children. |
| `CODEX_BROKER_PASSTHROUGH_ENV` | empty | CSV allowlist of exact environment variable names copied into app-server child processes in addition to the safe base environment. |

The broker uses the profile `codex-home` as `CODEX_HOME`, where `auth.json` and
the broker-managed permission configuration live. App-server children get a
separate non-secret `HOME` under `workspaces/runtime-homes`; auth commands use
the profile home. The child process environment is otherwise scrubbed.

## Turn execution and pooling

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_MAX_ACTIVE_TURNS` | `0` | Global active-turn cap. `0` uses the broker's bounded 32-worker default; same-thread serialization still applies. |
| `CODEX_BROKER_MAX_QUEUED_TURNS` | `1000` | Maximum turns waiting behind active turns. Further queue requests fail closed. |
| `CODEX_BROKER_POOL_IDLE_TTL_SECONDS` | `900` | Idle app-server children older than this are closed. Set `0` to disable idle sweeping. |
| `CODEX_BROKER_REQUEST_TIMEOUT_SECONDS` | `60` | Timeout for JSON-RPC request/response calls to an app-server child. |
| `CODEX_BROKER_TURN_TIMEOUT_SECONDS` | `0` | Maximum wall time for a Codex turn. `0` disables broker-level turn timeout. |
| `CODEX_BROKER_HOST_RESPONSE_TIMEOUT_SECONDS` | `30` | Time an app-server approval, permission request, user-input prompt, or MCP elicitation waits for host resolution before fallback. |
| `CODEX_BROKER_SANDBOX_PREFLIGHT` | `required` on Linux, otherwise `warn` | Runs a bounded no-model managed-sandbox canary once at startup. `required` makes readiness and managed turns fail closed unless it is healthy; `warn` reports the result but permits work; `disabled` skips it. |
| `CODEX_BROKER_SANDBOX_DENY_PATHS` | empty | Path-separator-delimited absolute control-plane paths to deny in every managed Codex permission profile, in addition to broker auth/state paths and `/run/secrets`. |
| `CODEX_BROKER_DANGER_FULL_ACCESS_KEY_FILE` | unset | File containing the separate key required to authorize `danger-full-access` on a request. The key is never accepted from a regular config profile or option. |

For user-input prompts, Codex may provide `autoResolutionMs`; the broker uses the smaller positive value between that prompt timeout and `CODEX_BROKER_HOST_RESPONSE_TIMEOUT_SECONDS`.

## Bundles, MCP, and hosted tools

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_ALLOWED_TOOL_COMMANDS` | empty | CSV allowlist for bundle-declared MCP server commands. Entries may be command names such as `node`, or exact absolute executable paths. |
| `CODEX_BROKER_ALLOWED_HOSTED_TOOL_URL_PREFIXES` | `http://127.0.0.1,http://localhost,http://host.docker.internal` | CSV allowlist for broker-hosted HTTP tool endpoints. Match is by parsed scheme and host, with optional explicit port and path prefix. |
| `CODEX_BROKER_ENABLE_INLINE_BUNDLES` | `false` | Enables `POST /v1/bundles/inline`. |
| `CODEX_BROKER_INLINE_BUNDLE_MAX_BYTES` | `262144` | Maximum serialized inline bundle payload size. |
| `CODEX_BROKER_HOSTED_TOOL_MAX_RESPONSE_BYTES` | `1048576` | Default maximum hosted-tool response or error body. A reviewed bundle may lower or override it. |

Inline bundles are stored by content digest. Re-sending the same payload is idempotent. A mounted bundle id cannot be shadowed by an inline bundle, and an accepted inline bundle id cannot later be reused with different content.

The complete manifest, overlay, MCP, and hosted-tool contract lives in
[Bundles and hosted tools](../bundles/bundles-and-hosted-tools.mdx).

## Logging, events, and shutdown

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_DEBUG_RAW_EVENTS` | `false` | When true, persists redacted raw app-server method and params beside normalized events. |
| `CODEX_BROKER_EVENT_SANITIZATION_MODE` | `safe` | `safe` replaces registered and sensitive-looking values in normalized persistence and all native/OpenAI egress. `raw` is trusted-debugging mode: normalized output is not transformed, but logs and raw debug fields remain redacted. |
| `CODEX_BROKER_RAW_EVENT_RETENTION_SECONDS` | `604800` | Startup pruning window for raw app-server method/params fields. Normalized events are preserved. |
| `CODEX_BROKER_HISTORY_RETENTION_SECONDS` | `7776000` | Retention for completed turns, normalized events, resolved interactions, audit logs, and closed-child records. `0` disables age pruning. |
| `CODEX_BROKER_MAX_EVENTS_PER_TURN` | `10000` | Maximum normalized events retained per turn. |
| `CODEX_BROKER_JSON_LOGS` | `true` | Emits structured JSON logs to stderr. Set false to suppress broker JSON logs. |
| `CODEX_BROKER_SHUTDOWN_MODE` | `interrupt` | `interrupt` or `drain`. Invalid values behave as `interrupt`. |
| `CODEX_BROKER_SHUTDOWN_DRAIN_TIMEOUT_SECONDS` | `30` | Drain wait before interrupting leftovers when shutdown mode is `drain`. |

Logs and raw event payloads are always redacted for registered secrets and
common API key, token, bearer, password, secret, credential, and cookie fields.
In `safe` mode, the same defense applies to normalized events, turns,
interactions, audits, historical reads, SSE, native responses, and
OpenAI-compatible responses. Streaming uses a small pending tail so a secret
split across deltas is not exposed.

Sanitization is not permission to send credentials to Codex. Host apps remain
responsible for keeping intentionally supplied prompt and input secrets out of
model context.

## Configuration profiles

| Variable | Default | Description |
| --- | --- | --- |
| `CODEX_BROKER_CONFIG_PROFILES_JSON` | unset | JSON object keyed by `configProfile` name. Takes precedence over the file variable. |
| `CODEX_BROKER_CONFIG_PROFILES_FILE` | unset | File containing the same JSON object. A configured missing, non-file, or empty path is a startup error. |

When no configuration profiles are configured, any request `configProfile`
name is accepted and no profile defaults are applied. When profiles are
configured, every request profile must exist. Requests that omit
`configProfile` use `default`, so include a `default` entry if omitted profile
fields should continue working.

## Configuration profile shape

```json
{
  "default": {
    "model": "gpt-5",
    "approvalsReviewer": "auto_review",
    "sandbox": "workspace-write",
    "enabledBundles": ["example-chat-v1"],
    "allowedWorkspaceRoots": ["/workspaces/app"]
  },
  "background-review": {
    "model": "gpt-5",
    "effort": "high",
    "summary": "auto",
    "webSearch": "enabled",
    "modelVerbosity": "low",
    "features": {
      "image_generation": false
    },
    "enabledBundles": ["document-jobs-v1"],
    "allowedWorkspaceRoots": ["/workspaces/app", "/host-data/jobs"]
  }
}
```

Supported keys:

| Key | Applies to | Description |
| --- | --- | --- |
| `approvalPolicy` | Codex thread | For managed sandboxes, the broker supplies a granular policy that allows reviewed permission requests but disables `sandbox_approval`. A caller may use `never` only with `approvalsReviewer: "user"`; other managed overrides must retain `sandbox_approval: false`. |
| `approvalsReviewer`, `approvals_reviewer` | Codex thread | `auto_review` (the managed default) or `user`. Auto-review reviews requested exceptions; it does not relax the filesystem profile. |
| `sandbox` | Codex thread | `read-only`, `workspace-write`, or separately authorized `danger-full-access`. Request options win, then bundle sandbox, then profile sandbox. Managed values map to broker-owned default-deny permission profiles; callers cannot supply a raw permission profile, runtime workspace roots, or sandbox policy. |
| `model` | Codex thread and turn | Passed to thread and turn calls unless overridden. |
| `personality` | Codex thread and turn | Passed to thread and turn calls unless overridden. |
| `serviceTier` | Codex turn | Service-tier id passed to `turn/start`; discover Fast and other supported ids from `/auth/models`. |
| `effort`, `reasoningEffort` | Codex turn and process config | Reasoning effort aliases. |
| `summary`, `reasoningSummary` | Codex turn | Reasoning summary aliases. |
| `outputSchema`, `output_schema` | Codex turn | JSON Schema for the final assistant message. |
| `webSearch`, `web_search` | Process config | Mapped to `-c web_search=<value>`. |
| `modelVerbosity`, `model_verbosity` | Process config | Mapped to `-c model_verbosity=<value>`. |
| `imageGeneration`, `features.image_generation` | Process feature config | Mapped to `features.image_generation=<value>`. |
| `features` | Process feature config | Object of feature names to values. |
| `enabledBundles`, `bundleIds`, `bundles` | Broker policy | Bundle allowlist for this profile. |
| `allowedWorkspaceRoots`, `workspaceRoots` | Broker policy | Per-profile cwd allowlist checked after global workspace or bundle validation. |

Managed sandbox roots are canonicalized and must be under both the global and
profile allowlists. For bundled managed turns with an explicit `cwd`, the broker
adds only the per-turn overlay as a second runtime root so the attached native
skill snapshot can be read; it never adds the original mounted skill source or
a workspace parent. The snapshot is content-digest verified, unique to its turn,
and rejects symbolic links and non-regular entries. The generated profiles deny
`:root`, permit only the minimal runtime reads and selected roots, and explicitly deny broker auth/state paths,
`/run/secrets`, configured extra deny paths, and common workspace credential
filenames. `workspace-write` permits its selected roots; `read-only` does not.
Credential deny rules use Codex 0.151 root-inclusive recursive `**/` patterns,
which protect both a workspace root and nested paths. Exact root masks are
intentionally omitted because Bubblewrap can try to materialize absent exact
deny targets when a turn has multiple runtime roots.
The legacy `sandboxPolicy`, `permissions`,
`permissionProfile`, and `runtimeWorkspaceRoots` fields are broker-managed and
are rejected from callers.

The cached no-model canary uses `command/exec` with its temporary workspace as
`cwd`. Pinned Codex `0.152.1` does not support `runtimeWorkspaceRoots` on that
command, so `cwd` is its runtime workspace root; normal thread and turn calls
receive the broker-canonicalized `runtimeWorkspaceRoots` field. The canary
therefore proves the materialized snapshot path under the production profile,
while parameter tests assert the exact ordered `[cwd, overlay]` runtime roots
used by normal managed calls.

To select `danger-full-access`, configure
`CODEX_BROKER_DANGER_FULL_ACCESS_KEY_FILE` and send its value in
`X-Codex-Broker-Danger-Full-Access-Key` with the otherwise authenticated
request. This explicitly bypasses the managed profile; do not use it for
untrusted work or to protect broker auth material.

### Model and reasoning selection

A turn can override profile defaults without modifying the profile:

```json
{
  "input": [{ "type": "text", "text": "Review these changes." }],
  "codexOptions": {
    "model": "gpt-5.6-sol",
    "effort": "high"
  }
}
```

Selection precedence is the turn's `codexOptions`, then the selected configuration profile, then Codex's current recommended model and model-specific defaults. `reasoningEffort` is accepted as an alias for `effort`. Model availability, supported effort values, and service tiers come from Codex and may differ by account, provider, and selected model.

Query `GET /v1/owners/{ownerId}/auth/models?profile=default` before rendering a picker. It returns `models` plus `nextCursor`, preserving App Server's supported/default reasoning efforts and service tiers, modalities, personality support, picker visibility, default state, and upgrade metadata. Pass the selected entry's `model` slug as `codexOptions.model`; its `id` is the stable catalog preset identifier. Offer Fast only when the selected model advertises a `serviceTiers` entry with `id: "fast"`, then send that id as `codexOptions.serviceTier`.

Use `cursor` for another page, `limit` from 1 through 500, and `includeHidden=true` only for trusted administrative views. Results are scoped to the owner-to-principal mapping and selected auth profile.

## Request-level options

Thread create accepts:

| Field | Description |
| --- | --- |
| `threadId` | Optional caller-supplied stable broker thread id. Reusing the same user/thread id returns the existing thread. |
| `authPrincipalId` | Optional assertion of trusted owner-to-principal policy. Omission defaults through policy to `ownerId`. |
| `profile` | Auth profile under the resolved principal. Defaults to `default`; canonical value is immutable for the thread. |
| `configProfile` | Configuration profile name. Defaults to `default`. |
| `runtimeProfile` | Deprecated alias for `configProfile`. |
| `hostApp` | Optional host app name for logs, metrics, and returned objects. |
| `bundleId` | Optional task bundle id. |
| `cwd` | Optional Codex working directory. Must be allowed by broker roots, bundle paths, and profile roots when configured. |

Turn start accepts:

| Field | Description |
| --- | --- |
| `input` | Required non-empty array of Codex input items. |
| `mode` | `reject`, `queue`, or `steer`. Defaults to `reject`. |
| `authPrincipalId` | Optional assertion that must resolve to the thread's immutable principal. |
| `profile` | Optional assertion that must match the thread's immutable canonical profile. It cannot override it. |
| `configProfile` | Overrides the thread config profile for this turn. |
| `runtimeProfile` | Deprecated alias for `configProfile`. |
| `hostApp` | Overrides or inherits the thread host app. |
| `bundleId` | Overrides or inherits the thread bundle id. |
| `cwd` | Overrides or inherits the thread cwd. |
| `codexOptions` | Canonical Codex option object. |
| `runtime` | Deprecated alias merged before `codexOptions`; `codexOptions` wins on conflicts. |
| `idempotencyKey` | Prevents duplicate work for retries on the same user/thread. |
| `productCorrelationId` | Host trace id persisted on events and logs. |
| `correlationId` | Alias for `productCorrelationId`. |
| `stream` | Present in OpenAPI for compatibility; current broker always persists events and returns `streamUrl`. |

## Docker build arguments

| Build arg | Default | Description |
| --- | --- | --- |
| `CODEX_VERSION` | `0.152.1` | Codex CLI release version without the `rust-v` prefix. |
| `TARGETARCH` | supplied by BuildKit | `amd64` maps to `x86_64`, `arm64` maps to `aarch64`. Other values fail the build. |

## Minimal local example

```env
CODEX_BROKER_HOST=127.0.0.1
CODEX_BROKER_PORT=3400
CODEX_BROKER_DATA_DIR=.data
CODEX_BROKER_ALLOWED_WORKSPACE_ROOTS=/path/to/workspaces
CODEX_BROKER_ALLOWED_BUNDLE_ROOTS=/path/to/bundles
CODEX_BROKER_ALLOWED_TOOL_COMMANDS=python,node
CODEX_BROKER_INTERNAL_KEY=dev-only-key
CODEX_BROKER_OPENAI_COMPAT_BINDINGS_FILE=/run/secrets/codex-broker-openai-bindings.json
CODEX_BIN=codex
CODEX_CREDENTIAL_STORE=file
```

Run with:

```bash
uv run codex-broker
```
