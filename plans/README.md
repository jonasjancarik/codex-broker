## Findings considered and rejected

- Expose Codex app-server WebSockets directly: rejected because app-server is
  JSON-RPC rather than an OpenAI REST/SSE contract, and its WebSocket transport
  is experimental.
- Accept `ownerId` or auth selectors from OpenAI request headers/body: rejected
  because it is neither drop-in compatible nor safe for owner isolation.
- Assemble responses from debug raw-event fields: rejected because those fields
  are optional, redacted, and retention-pruned diagnostics.
- Treat reviewed Codex bundles/MCP tools as caller-defined OpenAI functions:
  rejected because their ownership and request/response lifecycles differ.
- Let ordinary callers select arbitrary permission profiles or full access:
  rejected because workspace isolation is a broker-enforced read boundary.
  `danger-full-access` requires separate authorization.
- Use `seccomp=unconfined` or privileged Docker mode as the Bubblewrap fix:
  rejected because the exact outer-container blocker must be diagnosed and the
  narrowest working production policy verified.
- Replace text skill references with native bundle skill inputs: rejected as a
  broker change because native skill inputs already exist; deployments should
  use the existing bundle field.
- Store both sanitized and uncensored event copies in Plan 002: deferred until
  there is a separate encrypted/admin-only storage and retention design.
